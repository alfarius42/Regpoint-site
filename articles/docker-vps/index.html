Docker для event-платформы: требования к серверу

Linux VPS, Docker-compose — shared-хостинг и Windows не подойдут. Пилот: 2 vCPU, 2–4 GB RAM; production на 3k+ участников — 4 vCPU, 8 GB. Закупка обычно спрашивает это до тендера, не после деплоя.

Конфигурации VPS

Параметр Пилот / первый event Production 3 000–5 000 участников
ОСUbuntu 22.04 LTS или Debian 12
CPU2 vCPU4 vCPU
RAM2 GB (4 GB с Промо.Про / OCR)8 GB
Диск20 GB SSD50 GB SSD, MySQL volume отдельно
СетьСтатический IP или A-запись; HTTPS до открытия регистрации

Staging на втором VPS — если правите форму за сутки до event. Хостинг РФ: Selectel, Timeweb Cloud, Beget VPS, МТС Cloud, Яндекс Cloud VPC.

Почему не shared-хостинг

Event-платформа на Docker-compose нуждается в root или привилегированном пользователе, отдельных портах для MySQL и reverse proxy, cron для бэкапов. На shared это либо запрещено, либо ломается при первом обновлении образа.

Сервер в годовом бюджете

VPS 3 000–8 000 ₽/мес — отдельная строка TCO, её нельзя «вшить» в лицензию. Без этой строки коробка кажется дешевле, чем есть на самом деле — см. сравнение с SaaS за 2–3 года. Turnkey-внедрение (45 000 ₽) не заменяет ежемесячный хостинг: сервер остаётся у клиента, мы не хостим прод за вас.

Типичные ошибки деплоя

Диск забит логами Docker — ротируйте journald и container logs до event, не в день check-in. Не открыли webhook-порт для ЮKassa или whitelist IP ФНС — платёж или проверка чека «зависает» в проде, хотя на staging работало. Бэкап mysqldump по cron без проверенного restore — «есть бэкап» не значит «можно восстановиться».

Хостинг в РФ

Если в договоре с участниками — обработка ПД в России, сервер тоже в РФ. Selectel, Timeweb Cloud, Beget VPS, МТС Cloud, Яндекс Cloud VPC — типичный выбор. ДЦ в Москве или СПб стабильнее по latency для check-in в реальном времени. Cloudflare — только на статику; проксировать API с ПД через CDN нельзя. Зачем вообще свой сервер — в материале self-hosted vs SaaS, юридический контекст — на странице 152-ФЗ на мероприятиях.

Деплой: что проверить до боевого event

Docker + docker-compose по runbook из лицензии. .env: DB_PASSWORD, LICENSE_KEY, APP_DOMAIN. Nginx или Caddy + HTTPS. Smoke-test: тестовый event, регистрация, check-in с планшета. Стек описан в разделе технологии и архитектура, пошаговый сценарий — как работает Рег.Поинт. Частая ошибка: не открыли webhook-порт для ЮKassa или не добавили whitelist IP ФНС — платёж или проверка чека «зависает» в проде, хотя на staging работало.

Ограничения

OCR чеков на слабом VPS (2 GB) может упираться в RAM при пике загрузок. Offline check-in на площадке не отменяет необходимость периодической синхронизации. Бэкап mysqldump по cron — ваша зона ответственности; без проверенного restore «есть бэкап» не значит «можно восстановиться». Нет DevOps — turnkey от 45 000 ₽, root остаётся у клиента.

FAQ

Можно ли использовать shared-хостинг?

Нет. Docker нужен root или привилегированный пользователь. Только VPS/VDS.

Сколько стоит сервер в годовом TCO?

Ориентир 3 000–8 000 ₽/мес. Считайте отдельно — см. сравнение с SaaS за 2–3 года.

Нужен ли выделенный сервер для каждого заказчика?

Не обязательно. Одна лицензия — один инстанс на юрлицо. Несколько заказчиков — через роли director и изоляцию на уровне приложения. Отдельное железо — только если ИБ клиента это требует.

Нужна помощь с деплоем на ваш сервер?

Поднимем compose, HTTPS и smoke-test. Сервер и данные остаются у вас.
