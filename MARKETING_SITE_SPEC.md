## 4. Технологии и интеграции

### 4.1 Стек сайта

| Слой | Технология |
|------|------------|
| Разметка | HTML5, семантические теги (`header`, `main`, `article`, `section`) |
| Стили | CSS3, CSS-переменные; без фреймворка или лёгкий reset |
| Скрипты | Vanilla JS (ES modules): i18n, модалка, lazy-load, cookie-баннер |
| Сборка (опц.) | `scripts/build-prod.py` → `dist/` + `regpoint-site.zip` для FTP |
| Хостинг | Shared-хостинг RU или Cloudflare Pages / GitHub Pages + домен `.ru` |
| HTTPS | Обязательно (Let's Encrypt) |

### 4.2 Jivo — чат и формы (единый сервис)

**Почему Jivo, а не Crisp:** Crisp — EU/US, персональные данные посетителей обрабатываются за рубежом → риск для 152-ФЗ. **Jivo** (ООО «Живой Сайт», РФ) закрывает **оба** канала сайта: живой чат и заявки на КП/демо — один виджет, один операторский кабинет, один DPA.

| Параметр | Значение |
|----------|----------|
| Подключение | `<script src="//code.jivosite.com/widget/XXXXX" async></script>` в `<body>` |
| Онлайн-чат | `jivo_api.open()` — кнопка «Связаться», умная модалка |
| Форма «КП / Демо» | **Jivo contact form** на `/contacts#demo`: embed или вызов формы из виджета; поля настраиваются в кабинете Jivo |
| Offline | Та же форма Jivo, когда операторы offline → уведомление на email оператора |
| Уведомления | Email / push в приложении Jivo оператору; опц. интеграция с CRM |
| 152-ФЗ | Один договор обработки ПД с Jivo (чат + формы); упоминание в `/privacy` |
| Кастомизация | Цвет `#243954`, приветствие и поля формы RU/EN в настройках Jivo |

**Настройка формы в Jivo (кабинет):** создать форму «Запрос КП / Демо» с полями §4.4; embed-код в блок `#demo` на `/contacts` и CTA на главной (якорь или `jivo_api.open()`).

**Альтернативы (если Jivo не подойдёт):** LiveTex, Chat2Desk, Usedesk — российские, с widget + формой; тогда тоже один vendor на оба канала.

### 4.3 Edge / serverless — зачем НЕ нужен

Cloudflare Workers / Yandex Cloud Functions понадобились бы, если:
- свой кастомный чат без SaaS;
- своя отправка email без стороннего form-сервиса;
- прокси к Telegram Bot API.

**Для v1 всё закрыто одним Jivo** (чат + форма). Отдельный serverless или второй form-сервис не нужен.

### 4.4 Форма «Запросить КП / Демо» (Jivo)

**Prod:** только **Jivo** — та же интеграция, что и чат (§4.2). Отдельный form-сервис не подключаем.

| Режим | Когда | Как |
|-------|-------|-----|
| **Embed-форма** | Страница `/contacts#demo`, CTA «Запросить КП / Демо» | Embed-код формы из кабинета Jivo в блок `#demo` |
| **Offline / вне часов** | Операторы недоступны | Автоматически та же форма Jivo в виджете |
| **EmailJS** | Dev/staging без Jivo | **Не prod** (серверы US) |

**Поля формы** (настроить в Jivo):

- Имя*
- Компания*
- Email*
- Телефон
- Интересующий модуль* (select: Рег.Поинт / Промо.Поинт / Промо.Про / Тикет.Поинт / Не знаю)
- Комментарий
- Чекбокс согласия на обработку ПД* + ссылка на `/privacy` (текст рядом с embed или в описании формы Jivo)

**Anti-spam:** настройки Jivo + honeypot в embed (если поддерживается) или captcha в кабинете Jivo.

### 5.1 Публичный прайс на сайте — рекомендация

**Да, для Рег.Поинт это хорошая практика** — при условии, что на сайте **list price**, а не полный коммерческий регламент.

| Плюс | Почему важно для нас |
|------|----------------------|
| **Доверие B2B** | Коробка 100–180k ₽: скрытый прайс вызывает подозрение «как SaaS, но дороже» |
| **SEO** | Запросы «стоимость регистрации на мероприятие программа», «лицензия check-in» — высокий intent |
| **Квалификация лидов** | Отсеивает бюджет &lt;80k до звонка; в Jivo приходят уже «прогретые» |
| **Отличие от SaaS** | Прозрачная лицензия + self-hosted vs «позвоните для цены» у enterprise |
| **Апсейлы «от»** | Показываем диапазоны SKU — клиент понимает TCO (лицензия + деплой + обучение) |

| Риск | Как смягчить на сайте |
|------|------------------------|
| Конкуренты видят цены | List price и так в КП; дифференциатор — коробка + 152-ФЗ, не цена |
| Enterprise ждёт скидку | Дисклеймер: «ориентир 2026, итоговая сумма — в КП» |
| Сложная сетка апсейлов | На сайте — **группы** SKU, не внутренние коды sales; диапазоны «от … ₽» |
| Коммерческие gate (§3.2, §3.5) | **Не публиковать** на сайте (Promo/Ticket gates — только в CRM/КП) |

**Что выносить на `/pricing`:** лицензии модулей, подписка Y2+, апгрейды, типовые внедрение/обучение/152-ФЗ консалтинг (§5.1–5.5 `BUSINESS_MODEL.md`).

**Что не выносить:** PART-REF, коридоры переговоров 70–90k, комиссии sales, архивный vs новый renewal в деталях — достаточно сноски «уточняйте при продлении».

**CTA на странице:** «Запросить КП» (Jivo-форма) — финальная цена всё равно в КП.
