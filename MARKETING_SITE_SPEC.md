## 4. Технологии и интеграции

### 4.1 Стек и архитектура сайта

**Архитектура:** MPA (Multi-Page Application) — **vanilla HTML + CSS + JavaScript, без сборки и без бэкенда.**

| Слой | Технология |
|------|------------|
| Разметка | HTML5, семантические теги (`header`, `main`, `article`, `section`) |
| Стили | CSS3, CSS-переменные (`css/tokens.css`); **без** Tailwind/Bootstrap в production |
| Скрипты | Vanilla JS в `js/*.js`; **без** bundler, **без** `npm` в корне |
| Навигация | Физические HTML-страницы, `<a href>` (не SPA) |
| Сборка для dev/prod | **Не используется** — файлы отдаются как есть |
| Интеграции | **Jivo** (чат), Яндекс.Метрика |
| Упаковка релиза (опц.) | `scripts/build-prod.py` — копия + минификация в `dist/` + zip для FTP |
| Хостинг | Shared-хостинг RU, загрузка статики по FTP |
| HTTPS | Обязательно (Let's Encrypt) |

Подробнее: `docs/ARCHITECTURE.md`.

### 4.2 Jivo — единственный канал связи

**Почему Jivo, а не Crisp:** Crisp — EU/US, персональные данные посетителей обрабатываются за рубежом → риск для 152-ФЗ. **Jivo** (ООО «Живой Сайт», РФ) — чат и заявки на КП/демо в одном виджете, один операторский кабинет, один DPA.

| Параметр | Значение |
|----------|----------|
| Подключение | `<script src="//code.jivo.ru/widget/COp1zDxNwg" async></script>` в `<body>` (через `js/jivo.js`) |
| Онлайн-чат | `jivo_api.open()` — все CTA, FAB «Чат», «Связаться», «Запросить КП / Демо» |
| Заявки КП / Демо | Посетитель пишет в чат; оператор квалифицирует и отправляет КП |
| Offline | Offline-режим Jivo в том же виджете → уведомление на email оператора |
| Уведомления | Email / push в приложении Jivo оператору; опц. интеграция с CRM |
| 152-ФЗ | Договор обработки ПД с Jivo; упоминание в `/privacy` |
| Кастомизация | Цвет `#243954`, приветствие RU/EN в настройках Jivo |

**Страница `/contacts#demo`:** блок с текстом и кнопкой «Написать в чат» (`data-action="jivo"`), без HTML-формы на сайте.

**Альтернативы (если Jivo не подойдёт):** LiveTex, Chat2Desk, Usedesk — российские виджеты с чатом.

### 4.3 Edge / serverless — зачем НЕ нужен

Cloudflare Workers / Yandex Cloud Functions понадобились бы, если:
- свой кастомный чат без SaaS;
- своя отправка email без стороннего сервиса;
- прокси к Telegram Bot API.

**Для v1 всё закрыто одним Jivo** (чат). Отдельный form-сервис или serverless не нужен.

### 4.4 Заявки «Запросить КП / Демо»

**Prod:** только **Jivo-чат** — отдельная форма на сайте не используется.

| Режим | Когда | Как |
|-------|-------|-----|
| **Онлайн** | Операторы доступны | `jivo_api.open()` → диалог в виджете |
| **Offline / вне часов** | Операторы недоступны | Offline Jivo в том же виджете |
| **EmailJS** | Dev/staging без Jivo | **Не prod** (серверы US) |

**Что просить в чате:** имя, компания, email, модуль, задача — оператор собирает в диалоге.

### 4.5 CTA и FAB — UX-поток

```
[Связаться]           → jivo_api.open()
[Запросить КП / Демо] → jivo_api.open()
[FAB «Чат»]           → jivo_api.open()
```

### 5.1 Публичный прайс на сайте — рекомендация

**Да, для Рег.Поинт это хорошая практика** — при условии, что на сайте **list price**, а не полный коммерческий регламент.

| Плюс | Почему важно для нас |
|------|----------------------|
| **Доверие B2B** | Коробка 100–180k ₽: скрытый прайс вызывает подозрение «как SaaS, но дороже» |
| **SEO** | Запросы «стоимость регистрации на мероприятие программа», «лицензия check-in» — высокий intent |
| **Квалификация лидов** | Отсеивает бюджет &lt;80k до звонка; в Jivo приходят уже «прогретые» |
| **Отличие от SaaS** | Прозрачная лицензия + self-hosted vs «позвоните для цены» у enterprise |
| **Апсейлы «от»** | Показываем диапазоны SKU — клиент понимает TCO (лицензия + деплой + обучение) |

| Риск | Как смягчить на сайте |
|------|------------------------|
| Конкуренты видят цены | List price и так в КП; дифференциатор — коробка + 152-ФЗ, не цена |
| Enterprise ждёт скидку | Дисклеймер: «ориентир 2026, итоговая сумма — в КП» |
| Сложная сетка апсейлов | На сайте — **группы** SKU, не внутренние коды sales; диапазоны «от … ₽» |
| Коммерческие gate (§3.2, §3.5) | **Не публиковать** на сайте (Promo/Ticket gates — только в CRM/КП) |

**Что выносить на `/pricing`:** лицензии модулей, подписка Y2+, апгрейды, типовые внедрение/обучение/152-ФЗ консалтинг (§5.1–5.5 `BUSINESS_MODEL.md`).

**Что не выносить:** PART-REF, коридоры переговоров 70–90k, комиссии sales, архивный vs новый renewal в деталях — достаточно сноски «уточняйте при продлении».

**CTA на странице:** «Запросить КП» (Jivo-форма) — финальная цена всё равно в КП.

### 14.4 SEO-требования

- Один **unique primary keyword** на URL в `content/pages.json`
- Статья = information intent; scenario = commercial intent — **не дублировать keyword**
- Title: `{keyword} — {benefit} | Reg.Point`
- Автоперелинковка: `content/pages.json` + `js/internal-links.js` по tags + **hub → child**

### 14.5 Hub → child (existing + дочерние)

- **Новые URL = child** — поле `"hub": "/scenarios/"` в `pages.json`
- **Условные child** — `"relatedHubs": ["/products/reg-point/"]` для product-hub
- Схема: `content/SCHEMA.md`
